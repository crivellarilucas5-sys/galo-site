# Story 2.1: Página Quiz — perguntas sobre o Galo

## Contexto

O site já no ar tem 5 páginas informativas (Home, História, Títulos, Estádio, Elenco). O quiz é a primeira página **interativa**: o torcedor testa o que sabe sobre história, títulos e curiosidades do clube, e sai com uma pontuação e uma faixa bem-humorada. Todas as perguntas são derivadas **somente** de fatos já verificados em [[../../agents/research/atletico-mineiro-facts]] — nada de fato inventado.

O princípio da casa continua valendo: **conteúdo é dado, não markup**. Pergunta, alternativas, gabarito, explicação e faixas de resultado vivem em `src/content/quiz.ts`, tipados; o componente só renderiza.

## Decisões de produto (fechadas pelo architect)

| Tema | Decisão | Por quê |
|---|---|---|
| Tipo de pergunta | Múltipla escolha, **exatamente 4 alternativas**, **1 correta** | Formato mais natural pra fatos (anos, nomes, competições); layout consistente; validação simples |
| Quantidade | **Alvo 10**, aceito **8–10** (validado em build) | Nem curto nem cansativo; "7 de 10" é leitura imediata. A faixa 8–10 dá folga caso a pesquisa não feche 10 fatos verificáveis |
| Mistura | Recomendado ~4 história · ~3 títulos · ~3 curiosidades (`category`) | Variedade; não é validado em build, é orientação pra pesquisa |
| Timer | **Nenhum** | Tom descontraído; timer também é barreira de acessibilidade (WCAG 2.2.1) |
| Fluxo | **Uma pergunta por tela**, na ordem do content: escolhe → **Confirmar** → feedback (certo/errado + explicação curta) → **Próxima** | O feedback imediato transforma erro em curiosidade aprendida — é o que dá graça ao quiz |
| Ordem | **Fixa** (perguntas e alternativas na ordem do content). Sem embaralhar na v1 | Embaralhar no render quebra hidratação SSG; ordem fixa deixa o comportamento determinístico e testável. A pesquisa distribui a posição da correta entre a/b/c/d |
| Resultado | Tela final: `"{acertos} de {total}"` + título da faixa + mensagem curta + **Jogar de novo** + links pra `/historia` e `/titulos` | Fecha o ciclo e devolve o torcedor ao conteúdo do site |
| Faixas | 3 faixas por **percentual** de acerto (funciona pra 8, 9 ou 10 perguntas) — ver tabela abaixo | Limiar em % não quebra se a quantidade de perguntas mudar |
| Estado | Só em memória (React state). Nada de localStorage, cookie, analytics ou compartilhamento | Site sem backend; zero dado do usuário |

### Faixas de resultado (conteúdo inicial de `quizResultTiers`)

| `minPercent` | Com 10 perguntas | Título | Mensagem sugerida (editável pelo copy) |
|---|---|---|---|
| 0 | 0–4 acertos | Torcedor de araque | "Ainda dá pra virar esse jogo — passa na nossa História e tenta de novo." |
| 50 | 5–7 acertos | Atleticano roxo | "Conhece o Galo de verdade. Mais um pouco de arquibancada e chega no topo." |
| 80 | 8–10 acertos | Nasceu vestindo preto e branco | "Você não torce pro Galo, você é o Galo." |

Regra: vale a faixa de **maior** `minPercent` tal que `percentual >= minPercent`, com `percentual = acertos / total × 100`. Com 8 perguntas: 0–3 / 4–6 / 7–8. Com 9: 0–4 / 5–7 / 8–9.

> Mensagens de faixa são copy, não fato — **não podem citar dado histórico** (ano, título, placar). Fato só entra via pergunta/explicação com `factRef`.

## Contrato de dados (descrição — o dev implementa)

Adicionar a `src/types/content.ts`:

```ts
export type QuizCategory = "historia" | "titulos" | "curiosidades";

/** Ids estáveis das alternativas dentro de uma pergunta. */
export type QuizOptionId = "a" | "b" | "c" | "d";

export interface QuizOption {
  id: QuizOptionId;
  label: string;                 // texto da alternativa
}

export interface QuizQuestion {
  id: string;                    // slug estável e único, ex.: "ano-fundacao"
  category: QuizCategory;
  prompt: string;                // enunciado, termina em "?"
  options: [QuizOption, QuizOption, QuizOption, QuizOption]; // exatamente 4 (tupla)
  correctOptionId: QuizOptionId; // gabarito por id, nunca por índice
  explanation: string;           // 1–2 frases mostradas após confirmar
  factRef: string;               // âncora no research (NÃO renderizado), ex.: "atletico-mineiro-facts#copa-libertadores-da-america"
}

export interface QuizResultTier {
  minPercent: number;            // 0–100, inclusivo
  title: string;
  message: string;
}
```

`src/content/quiz.ts` (dado puro, sem React) exporta:
- `quizQuestions: QuizQuestion[]` (via `satisfies`, padrão do projeto)
- `quizResultTiers: QuizResultTier[]` (as 3 faixas acima)

`src/lib/quiz.ts` (funções puras, sem React):
- `scoreQuiz(questions: QuizQuestion[], answers: Partial<Record<string, QuizOptionId>>): number` — conta acertos; pergunta sem resposta conta 0.
- `getResultTier(score: number, total: number, tiers: QuizResultTier[]): QuizResultTier` — regra da tabela acima.
- `assertQuizIntegrity(questions, tiers): void` — lança `Error` com mensagem clara se: quantidade fora de 8–10; `id` de pergunta duplicado; ids de alternativa não forem exatamente `a,b,c,d` sem repetição; `correctOptionId` não existir nas alternativas; `prompt`/`explanation`/`factRef`/`label` vazio; tiers sem uma faixa `minPercent: 0`, com `minPercent` duplicado ou fora de 0–100.

## Acceptance Criteria

- [ ] **AC1 — Navegação.** `src/content/navigation.ts` ganha `{ label: "Quiz", href: "/quiz" }` como **último** item, depois de Elenco. Header desktop, menu mobile (Sheet) e footer passam a mostrar o item sem mudança nos componentes (todos já consomem `navItems`). Em `/quiz`, o link tem `aria-current="page"`. No breakpoint `md` (768px), os 6 itens cabem numa linha sem quebra nem overflow horizontal. **Nav e rota entram na mesma mudança** — o link nunca vai pro ar apontando pra 404.
- [ ] **AC2 — Rota.** `src/app/quiz/page.tsx` existe e o `pnpm build` a lista como estática (`○ /quiz`). A página tem um único `<h1>` ("Quiz do Galo" ou equivalente do copy) e uma intro curta, ambos renderizados no servidor.
- [ ] **AC3 — Conteúdo é dado.** Perguntas, alternativas, gabarito, explicações e faixas vêm **só** de `@/content/quiz`, tipados com as interfaces acima. Verificação: nenhum `prompt`, `label` de alternativa ou `title` de faixa de `quiz.ts` aparece literalmente em arquivo `.tsx` (`grep` de 3 prompts em `src/**/*.tsx` → 0 ocorrências). O componente recebe tudo por props.
- [ ] **AC4 — Integridade em build.** `page.tsx` chama `assertQuizIntegrity(quizQuestions, quizResultTiers)` no escopo do servidor; conteúdo inválido **quebra o `pnpm build`**. Evidência no Dev Agent Record: uma execução com conteúdo quebrado de propósito (ex.: `correctOptionId` inexistente) falhando, e depois o build verde com o conteúdo real.
- [ ] **AC5 — Perguntas reais e rastreáveis.** `quiz.ts` tem 8–10 perguntas transcritas do entregável da pesquisa (ver Dependências), cada uma com `factRef` apontando pra uma seção existente de [[../../agents/research/atletico-mineiro-facts]]. Zero `TODO(pesq)` em `quiz.ts` no fechamento. O dev **não escreve pergunta**.
- [ ] **AC6 — Fluxo da pergunta.** Mostra `"Pergunta {n} de {total}"`, o enunciado e as 4 alternativas. **Confirmar** sem seleção não avança e mostra a mensagem inline "Escolha uma alternativa", associada ao grupo via `aria-describedby`. Depois de confirmar: as alternativas ficam travadas, a correta é destacada e, se o usuário errou, a escolhida é marcada como errada. O feedback diz **em texto** "Acertou!" / "Não foi dessa vez — a resposta certa é {label}.", mais a `explanation` (cor e ícone só complementam o texto — WCAG 1.4.1). O botão vira **Próxima pergunta** (ou **Ver resultado** na última). Sem timer em lugar nenhum.
- [ ] **AC7 — Pontuação correta.** A tela de resultado mostra `"{acertos} de {total}"`, calculado com `scoreQuiz` a partir das respostas confirmadas, e a faixa vem de `getResultTier`. Evidência no Dev Agent Record, jogando com o conteúdo real: (a) tudo certo → `total de total` e faixa 3; (b) tudo errado → `0 de total` e faixa 1; (c) exatamente no limiar de 50% e (d) um acerto abaixo dele → faixas 2 e 1, respectivamente. Recalcular a pontuação de outro jeito dentro do componente é proibido: a fonte única é `lib/quiz.ts`.
- [ ] **AC8 — Resultado e recomeço.** A tela final tem título + mensagem da faixa, botão **Jogar de novo** (zera estado e respostas e volta pra pergunta 1) e links internos pra `/historia` e `/titulos`.
- [ ] **AC9 — Teclado e leitor de tela.**
  - Cada pergunta é um `<form>` com `<fieldset>` + `<legend>` (o enunciado) e `<input type="radio">` nativos com `<label>`. Tab entra no grupo, setas trocam a alternativa e Enter/Espaço confirmam, sem handler de teclado customizado para as opções.
  - Foco gerenciado: ao confirmar → foco no botão **Próxima**/**Ver resultado**; ao avançar → foco no enunciado da nova pergunta (`tabIndex={-1}`); na tela de resultado → foco no heading do resultado; em **Jogar de novo** → foco no enunciado da pergunta 1.
  - O feedback de acerto/erro e a troca de pergunta são anunciados por uma região `aria-live="polite"` única e persistente.
  - Foco visível em tudo que é interativo (tokens existentes). Hierarquia de headings sem pular nível (`h1` página → `h2` pergunta/resultado).
  - Jogar o quiz inteiro, do começo até **Jogar de novo**, **só com teclado**, e registrar no Dev Agent Record.
- [ ] **AC10 — SEO e infra.** `metadata` via `buildMetadata({ title: "Quiz", description, path: "/quiz" })`, com `description` de 50 a 160 caracteres. `src/app/sitemap.ts` inclui `/quiz`. Nenhum JSON-LD novo.
- [ ] **AC11 — Robustez de render.** Sem aviso de hidratação no console (ordem fixa, sem `Math.random`/`Date` no render). Transições respeitam `prefers-reduced-motion`. O HTML servido já traz o `h1`, a intro e a pergunta 1 visíveis, sem `opacity:0` serializado (lição do H3, épico 1). Um `<noscript>` avisa que o quiz precisa de JavaScript. Com isso, `pnpm lint`, `pnpm typecheck` e `pnpm build` terminam com exit 0.

## Notas técnicas

- **Divisão server/client:** `page.tsx` importa `quizQuestions`/`quizResultTiers`, chama `assertQuizIntegrity` e passa os dados por props pro `<QuizRunner questions={...} tiers={...} />`. O `QuizRunner` não importa de `@/content`. É o padrão de `sections/` já existente ("recebe dados por props").
- **Estado:** um `useReducer` com `{ index, selected, confirmed, answers }` resolve. A pontuação se deriva com `scoreQuiz` no momento do resultado, sem contador paralelo.
- **Gabarito no bundle:** as respostas vão pro cliente. É aceitável num quiz de entretenimento sem prêmio, e está registrado no ADR-001.
- **Visual:** reusar `Card`, `Button`, `Badge` (categoria) e tokens do `@theme`. Consultar `docs/smart-memory/agents/ux/` (DIGEST, components, design-direction). Se o ux ainda não tiver direção específica pro quiz, seguir o padrão visual de `/elenco` (eyebrow + h1 display uppercase), sem inventar paleta.
- **Reveal:** se usar `Reveal` na intro, a pergunta 1 **não** pode depender de animação pra aparecer (AC11).
- **Sem test runner no projeto:** a verificação de AC4/AC7 é por build + jogo manual documentado. Não adicionar Vitest/Jest nesta story.
