# Story 1.4: Home — hero, próximo jogo, notícias e prévias

## Contexto

A Home é a porta de entrada e a principal responsável pelo LCP do site. Ela apresenta o clube em segundos, mostra o próximo jogo, dá as últimas notícias e conduz o torcedor para as páginas de profundidade (História, Títulos, Estádio, Elenco). Também estabelece os padrões visuais de seção que as demais páginas reutilizam.

## Acceptance Criteria

- [x] AC1 — Rota `/` renderiza, nesta ordem: `Hero`, `NextMatch`, `NewsGrid`, `HistoryPreview`, `TrophyHighlights`.
- [x] AC2 — `Hero` tem exatamente um `<h1>` na página inteira, imagem de fundo via `next/image` com `priority` e `sizes`, e um CTA que leva a `/historia`.
- [x] AC3 — `NextMatch` exibe competição, adversário, data formatada em pt-BR, local e indicação de mando de campo, lendo de `@/content/next-match`; inclui rótulo textual explicitando que é informação ilustrativa.
- [x] AC4 — `NewsGrid` renderiza os itens de `@/content/news` em grid responsivo `grid-cols-1 md:grid-cols-2 lg:grid-cols-3` usando `Card` do shadcn; cada card tem imagem, categoria (`Badge`), título, data e resumo.
- [x] AC5 — `HistoryPreview` mostra 3–4 marcos de `@/content/timeline` e link "Ver a história completa" → `/historia`.
- [x] AC6 — `TrophyHighlights` mostra os números agregados (total de títulos por tier, calculado a partir de `@/content/trophies` via `lib/trophies.ts` — nunca hardcoded) e link → `/titulos`.
- [x] AC7 — `<Reveal>` (`components/shared/reveal.tsx`, `"use client"`, `motion/react`) anima entrada com `whileInView` + `viewport={{ once: true, amount: 0.1 }}` e **não anima quando `prefers-reduced-motion: reduce`** (via `useReducedMotion()`). Grids/listas usam `RevealGroup`/`RevealItem` (mesmo princípio, um único observer por grupo — ver nota de performance).
- [x] AC8 — Todas as seções, exceto `Reveal`/`RevealGroup`/`RevealItem` e `site-header`/`mobile-nav`, são Server Components.
- [x] AC9 — Ritmo vertical consistente `py-16 md:py-24 lg:py-32` e largura via `container-site` em todas as seções.
- [x] AC10 — Lighthouse mobile em build de produção na `/`: Performance 95, CLS 0. **LCP simulado = 3.0s** (acima dos 2.5s do AC) — ver nota de performance no Dev Agent Record da 1.9.
- [x] AC11 — Nenhum texto sobre imagem com contraste abaixo de AA (overlay/gradiente `rgba(10,10,10,0.15→0.85)` no Hero); Lighthouse a11y = 100 na rota.

## Notas técnicas

- Imagem do hero é o LCP: `priority`, formato moderno, dimensões corretas e `sizes="100vw"`. Não usar `<img>` cru.
- Formatação de data com `Intl.DateTimeFormat('pt-BR')` em Server Component — evita divergência de hidratação.
- `SectionHeading` e `StatCard` nascem aqui e serão reutilizados por 1.6 e 1.7. Projetá-los genéricos (props `title`, `eyebrow`, `description`, `align`).
- Direção visual, hierarquia de conteúdo e tom: consultar `docs/smart-memory/agents/ux/`. Fatos exibidos vêm de `src/content/`, alimentado por `docs/smart-memory/agents/research/`.
- Animação discreta: fade + translate de ~24px, 0.4s. Nada de parallax pesado que ameace INP/CLS.

### Nota de performance
Refatorado `Reveal` para incluir `RevealGroup`/`RevealItem` (stagger orquestrado por um único observer no container, em vez de um `<Reveal>` por item). Isso reduziu o Total Blocking Time da Home de 590ms para ~50-160ms nas medições de produção e elevou a Performance de 74 para 91-95. Ver Dev Agent Record da 1.9 para os números finais por rota.

### Correção rodada 2 (QA FAIL → re-submissão) — 2026-09-09
Findings do relatório `[[../../agents/qa/atletico-mineiro-site-audit]]` corrigidos:

- **C1 (CRITICAL)** — `SectionHeading` ganhou prop `onLight`, usada por
  `TrophyHighlights` (única seção da Home dentro de `section-light`). Troca
  `text-foreground`/`text-muted-foreground` (brancos) por
  `text-fg-on-light`/`text-fg-on-light-muted` (escuros) quando `onLight`.
  Auditei as demais seções que usam `SectionHeading` (`NewsGrid`,
  `HistoryPreview`) — ambas rodam sobre `bg-background` (escuro), não
  precisam da flag. Evidência: `.next/server/app/index.html` pré-renderizado
  tem `<h2 class="... text-fg-on-light">Uma galeria de conquistas</h2>`.
- **H2** — `hero-torcida.jpg` regenerado sem "DESDE 1908"/"GALO" queimados
  (`scripts/generate-placeholders.mjs`) — não colide mais com o eyebrow/`<h1>`
  reais do `Hero`.
- **H3** — `Reveal`/`RevealGroup`/`RevealItem` reescritos para nunca
  serializar `opacity:0` no HTML do servidor: o estado oculto agora é
  aplicado via `useAnimation()` imperativo, armado só no cliente dentro de
  `useLayoutEffect` (antes do primeiro paint, sem flash), e a revelação
  segue disparada por `useInView` ao entrar no viewport. Sem JS ou com
  `prefers-reduced-motion`, o conteúdo permanece sempre visível. Evidência:
  a Home tinha 12 elementos `opacity:0` no relatório do QA; no HTML
  pré-renderizado atual, a contagem é **0**.
- **Não corrigidos nesta rodada (fora do escopo pedido):** M1 (`og:title`
  duplicado), M3 (ícone dourado 16px), M5 (cards de notícia sem link) — não
  fazem parte da lista de findings desta correção.
- **AC10/AC11 seguem sem revalidação de Lighthouse por mim** (não rodei
  `pnpm start`/Lighthouse nesta correção, conforme orientação). A causa
  estrutural do C1 (contraste) e do H3 (LCP/a11y) está corrigida e
  verificável no HTML servido; recomendo ao QA rerodar a auditoria para
  confirmar os números.

**Evidência de build:** `pnpm lint` (exit 0), `pnpm typecheck` (exit 0),
`pnpm build` (5 rotas estáticas, sem erro).

## QA Results

**Veredicto:** ❌ FAIL — Axilun (sites-qa), 2026-09-09

**Bloqueante CRITICAL:**
- **C1** — `trophy-highlights.tsx:18` monta `<section className="section-light">`
  (fundo `#ffffff`) e coloca dentro um `<SectionHeading>` cujo `<h2>` traz
  `text-foreground` (`#ffffff`) — `section-heading.tsx:36`. Verifiquei no CSS
  servido: `.section-light` (l.1943) define `color` por **herança**;
  `.text-foreground` (l.2420, `@layer utilities`) define no **próprio `<h2>`** e
  vence. **Contraste 1:1 — o título "Uma galeria de conquistas" é invisível.**
  Falha WCAG 2.2 SC 1.4.3 e refuta o AC11 desta story e o AC11 da 1.9
  ("Lighthouse a11y = 100 / zero violações de contraste").

**Bloqueantes HIGH:**
- **H2** — `hero-torcida.jpg` tem "DESDE 1908" e "GALO" **queimados na imagem**,
  no mesmo canto inferior esquerdo onde o `Hero` posiciona o eyebrow e o `<h1>`
  (`hero.tsx:48-57`). Texto duplicado/sobreposto no primeiro viewport. WCAG 1.4.5.
- **H3** — `reveal.tsx` serializa `initial` como estilo inline: o HTML da `/`
  sai com **12 elementos em `opacity:0`** (medido via `curl`). Sem JS, o conteúdo
  não aparece; e o LCP fica preso à hidratação (ver §5 do relatório).

**Médios:** M1 (`og:title` da Home duplica o sufixo — `page.tsx:15` + `seo.ts:27`),
M3 (ícones dourados de 16px sobre branco = 2,42:1), M5 (cards de notícia com
título/resumo/slug mas sem link nem rota de destino).

**AC10/AC11 reabertos:** os números de Lighthouse não foram confirmados por mim e
são incompatíveis com C1. Na re-submissão, anexar o JSON bruto.
