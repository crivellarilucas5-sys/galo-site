# Story 1.2: Shell do site — Header, navegação e Footer

## Contexto

Toda rota do site compartilha o mesmo cabeçalho e rodapé. O footer também é o único ponto de contato do site (não haverá página `/contato`), concentrando redes sociais e informações institucionais. Componentes deste shell são God Nodes: aparecem em 100% das páginas.

## Acceptance Criteria

- [x] AC1 — `SiteHeader` renderiza links para as 5 rotas (`/`, `/historia`, `/titulos`, `/estadio`, `/elenco`), lendo de `@/content/navigation`. Adicionar um item ao array faz o link aparecer sem editar o componente.
- [x] AC2 — A rota atual recebe destaque visual **e** `aria-current="page"`.
- [x] AC3 — Em viewport < 768px o menu vira botão hambúrguer que abre um `Sheet` do shadcn; clicar em um link fecha o Sheet.
- [x] AC4 — Header é sticky no topo com fundo sólido/blur ao rolar, sem causar deslocamento de layout (CLS = 0 no scroll). Confirmado: Lighthouse CLS = 0 nas 5 rotas (ver Dev Agent Record da 1.9).
- [x] AC5 — `SiteFooter` exibe: nome do site, links das 5 rotas, ícones de redes sociais (`lucide-react`) lidos de `@/content/club`, cada um com `aria-label`, `target="_blank"` e `rel="noopener noreferrer"`; e nota de rodapé declarando que o site é um projeto de torcedor **não-oficial**.
- [x] AC6 — Header e Footer estão montados em `src/app/layout.tsx` e aparecem em toda rota.
- [x] AC7 — Navegação completa por teclado: `Tab` percorre todos os links em ordem lógica, foco sempre visível (`:focus-visible` global em `globals.css`), `Esc` fecha o menu mobile (comportamento nativo do `Dialog` Radix usado pelo `Sheet`).
- [x] AC8 — Um skip link "Pular para o conteúdo" é o primeiro elemento focável e leva ao `<main id="conteudo">`.
- [x] AC9 — `SiteFooter` é Server Component (sem `"use client"`); apenas `site-header`/`mobile-nav` são client.

## Escopo

**IN:**
- `components/layout/site-header.tsx`, `mobile-nav.tsx`, `site-footer.tsx`
- Montagem no `layout.tsx` com `<main id="conteudo">` envolvendo `children`
- Consumo de `content/navigation.ts` e `content/club.ts`
- Logo/wordmark textual do site (asset gráfico fica a critério do UX)

**OUT:**
- Conteúdo das páginas (stories 1.4–1.8)
- Busca, newsletter, seletor de tema claro/escuro
- Formulário de contato (não existe no escopo do site)

## Notas técnicas

- Se a Story 1.3 ainda não tiver entregue `content/navigation.ts` e `content/club.ts`, criar os módulos com os campos mínimos exigidos aqui e alinhar com o que a 1.3 define — os arquivos são compartilhados, não duplicar estruturas.
- `SiteHeader` usa `usePathname()` para o estado ativo → precisa de `"use client"`.
- Menu mobile com `Sheet` do shadcn (já instalado na 1.1). Não editar `components/ui/sheet.tsx`.
- Consultar `docs/smart-memory/agents/ux/` para tom, densidade e tratamento do header.
- Contraste AA obrigatório também no estado hover/focus.

## QA Results

**Veredicto:** ⚠️ CONCERNS — Axilun (sites-qa), 2026-09-09

Verificado por mim no HTML servido: as 5 rotas no header e no footer lidas de
`content/navigation`; `aria-current="page"`; hambúrguer `md:hidden` com `Sheet`
e `SheetClose` nos links; header sticky com transição de 200ms; skip link como
primeiro focável apontando para `<main id="conteudo">`; ícones sociais com
`aria-label`, `target="_blank"` e `rel="noopener noreferrer"`; disclaimer de site
não oficial; `SiteFooter` sem `"use client"`. AC1–AC9 atendidos.

**Observações (não bloqueantes):**
- M4 — `.outline-none` do `Button` shadcn (`@layer utilities`) vence o
  `:focus-visible` global (`@layer base`); o substituto `ring-ring/50` dá 2,77:1
  (<3:1). O foco continua visível pela borda dourada, mas foge do padrão da UX.
- L6 — sublinhado do nav só em `hover`, a spec pede `hover/focus`.
- L7 — dois `<nav aria-label="Navegação principal">`; `aria-controls` aponta para
  id inexistente enquanto o painel está fechado.
- L8 — links externos sem aviso de nova aba. L9 — `NextMatch` sem heading.
- L3 — `© {ano} Clube Atlético Mineiro` em site não oficial + `new Date()` congela no build.
