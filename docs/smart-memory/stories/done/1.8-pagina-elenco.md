# Story 1.8: Página Elenco — time atual

## Contexto

O torcedor espera ver o time. Como não há backend nem integração com fonte de dados de elenco, esta página é **estática e explicitamente ilustrativa** — decisão arquitetural registrada para evitar que o site pareça desatualizado sem avisar o visitante. É a página mais simples do épico e a candidata natural a ser cortada se o escopo apertar.

## Acceptance Criteria

- [x] AC1 — Rota `/elenco` existe e é gerada como estática no build.
- [x] AC2 — Jogadores de `@/content/squad` agrupados por posição na ordem: goleiro → defesa → meio → ataque, cada grupo com `<h2>` (via `lib/squad.ts#groupByPosition`).
- [x] AC3 — **(REVISADO pelo architect em 2026-09-09 — ver decisão abaixo; FECHADO pelo sites-dev-alpha em 2026-09-09.)** Card de jogador exibe imagem (`next/image`), nome, número (quando houver) e posição. O `alt` da imagem descreve **o que a imagem realmente mostra**, nunca o que o card afirma ao lado:
  - **AC3.1** — Quando a imagem renderizada é a silhueta genérica (`player.photo` ausente → `placeholder-silhueta.png`), a imagem é **decorativa**: `alt=""`. Ela não carrega informação alguma que o texto adjacente (nome, número, posição) já não carregue, e é idêntica para todos os jogadores. **Proibido usar o nome do jogador como `alt` de silhueta.**
  - **AC3.2** — Só quando `player.photo` apontar para uma fotografia real e individual do jogador o `alt` pode nomeá-lo (`"{nome}, {posição}"`). Hoje nenhum registro de `squad.ts` tem `photo` — este ramo é contrato para o futuro, não código morto a ser exercitado agora.
  - **AC3.3 (verificação)** — No HTML servido de `/elenco`: nenhum atributo `alt` contém nome de jogador enquanto todos os `src` apontarem para `placeholder-silhueta.png`; as 20 imagens saem com `alt=""`. Comando de referência: `curl -s localhost:3000/elenco | grep -o 'alt="[^"]*"' | sort -u`.
  - **AC3.4** — A informação "elenco ilustrativo" continua sendo responsabilidade do aviso visível do AC5 (`role="note"`, lido por leitor de tela), **não** do `alt` repetido 20 vezes. Não trocar um `alt` mentiroso por um `alt` verborrágico.
- [x] AC4 — Grid responsivo `grid-cols-2 md:grid-cols-3 lg:grid-cols-4`.
- [x] AC5 — Aviso visível na página (`role="note"` com ícone e texto, não apenas comentário) informando que o elenco é ilustrativo e pode não refletir o plantel atual.
- [x] AC6 — Posição sem jogadores no dataset não renderiza cabeçalho de grupo vazio (`groupByPosition` filtra grupos vazios).
- [x] AC7 — Fotos ausentes caem em placeholder consistente (`public/images/squad/placeholder-silhueta.png`, gerado), sem quebrar o grid nem gerar CLS (`next/image fill` em container `aspect-square`).
- [x] AC8 — `metadata` com `title`, `description` e canonical `/elenco`.
- [x] AC9 — Entrada animada com `RevealGroup`/`RevealItem`, respeitando `prefers-reduced-motion`; Lighthouse a11y = 100 na rota (build de produção).

### Decisão do Architect sobre o AC3 — REVISÃO DO CRITÉRIO

**Decisão:** Zaelion (sites-architect), 2026-09-09 — em resposta ao M8 do QA
([[../../agents/qa/atletico-mineiro-site-audit]] §4).

**Texto anterior:** *"Card de jogador exibe foto (`next/image` com `alt` = nome do
jogador), nome, número (quando houver) e posição."*

#### Por que o AC estava errado (e a culpa é da story, não do dev)
Verifiquei `src/content/squad.ts` e `src/components/sections/squad-grid.tsx`:
nenhum dos 20 registros tem `photo`, então o `??` do componente resolve **sempre**
para `placeholder-silhueta.png` — a mesma silhueta genérica nas 20 posições. Com
`alt = player.name`, o HTML afirma para o leitor de tela que aquela imagem é o
Rafael Menezes. Ela não é. A associação nome↔imagem **não existe** no dado, e o
site inteiro já declara isso em voz alta (`squadIsIllustrative = true`, aviso
`role="note"` do AC5, comentário de topo de `squad.ts`).

O defeito é de **AC**, não de implementação: o dev escreveu exatamente o que a
story pediu. Por isso a correção começa aqui e o `squad-grid.tsx` só é tocado
depois — o QA acertou ao exigir essa ordem.

#### Princípio que passa a valer
> `alt` descreve a imagem entregue, nunca a intenção do dado ao lado dela.

Um placeholder idêntico repetido N vezes é, por definição, decorativo:
`alt=""` (WCAG 2.2 — H67). As três alternativas foram consideradas:

| Opção | Por que não / por que sim |
|---|---|
| `alt="{nome}"` (atual) | ✗ Afirma associação inexistente (WCAG 1.1.1) **e** duplica o nome já presente no `<p>` do card — leitor de tela ouve o nome duas vezes por card, 40× na página |
| `alt="Silhueta genérica — foto não disponível"` | ✗ Honesto, porém repetido 20× vira ruído puro; a informação já está no aviso do AC5, num lugar só, onde pertence |
| **`alt=""` (escolhida)** | ✓ Remove a imagem da árvore de acessibilidade sem mentir nem poluir. O card continua totalmente legível: nome + número + posição são texto real |

#### Efeito no status
AC3 volta a `[ ]` e integra o pacote de correção do `sites-dev-alpha` desta
rodada, junto com o H3 (`opacity:0`) que reabriu o AC9. AC1, AC2 e AC4–AC8
seguem `[x]` — o QA os confirmou na letra.

#### Fora do escopo desta revisão (encaminhado ao lead)
- **Redação do AC5:** o QA observa que *"podem não refletir o plantel atual"*
  sugere jogadores reais desatualizados, quando os 20 nomes são **fictícios**.
  Concordo com o mérito, mas AC5 não está no meu escopo desta task — registro
  para o lead priorizar numa próxima rodada.
- **L10** (`truncate` sem `title`) permanece como está: baixo, não bloqueante.

## Notas técnicas

- Agrupamento por posição é função pura na página; `SquadGrid` recebe `players` já filtrados.
- Nomes de jogadores envelhecem rápido: manter o dado enxuto (nome, posição, número) reduz a superfície de erro. Não incluir estatísticas, contratos ou valores.
- Placeholder de foto: uma silhueta neutra em `public/images/`, não uma foto real de terceiro.
- Consultar `docs/smart-memory/agents/ux/` para o tratamento do card (recorte, hover) e `agents/research/` caso haja lista de referência.
